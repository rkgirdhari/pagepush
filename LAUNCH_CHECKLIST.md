# Launch Checklist

Tracking checklist from the product spec (section 10), expanded with the concrete
steps needed to actually clear each item for this codebase.

## Facebook App setup (blocking — required before any real posting works)

- [ ] Create a Facebook App at [developers.facebook.com](https://developers.facebook.com/apps)
      with the "Business" app type.
- [ ] Add the **Facebook Login** product and configure a valid OAuth redirect URI
      using `chrome.identity.getRedirectURL("facebook")` (printed to the console the
      first time `connectFacebookPages()` runs in dev, or computable as
      `https://<extension-id>.chromiumapp.org/facebook`).
- [ ] Replace `FACEBOOK_APP_ID` in `src/background/auth.js` with your real App ID.
- [ ] Request the following permissions in App Review: `pages_show_list`,
      `pages_manage_posts`, `pages_read_engagement`, `pages_manage_metadata`.
- [ ] Submit for **App Review** (budget 4–6 weeks per the spec). Facebook requires a
      screencast showing the exact "connect → compose → post" flow and a privacy
      policy URL (see `PRIVACY_POLICY.md`, must be hosted at a public URL before
      submission).
- [ ] Add test users / Page admins to the app's **Roles** while in Development Mode so
      you can test end-to-end before App Review passes.

## Chrome Web Store submission

- [ ] Replace the placeholder icons in `icons/` (generated by
      `scripts/generate_icons.py`) with final branded artwork at 16/48/128px.
- [ ] Privacy policy page is live and linked from the Store listing (same doc as
      `PRIVACY_POLICY.md`, hosted somewhere public).
- [ ] Screenshots showing: capturing from ChatGPT, the side panel compose view, the
      Facebook preview, and a successful post confirmation.
- [ ] Short video demo of the golden path, for both Facebook App Review and the Store
      listing.
- [ ] Fill in the Store's permission justification fields using the "Permissions we
      request and why" section of `PRIVACY_POLICY.md` as source text.

## Technical validation before submission

- [ ] Rate limit handling tested: trigger Facebook's `code 4`/`code 17` responses (or
      mock them) and confirm `FacebookApiError.suggestion` renders a sane message in
      the side panel.
- [ ] Token refresh verified after the long-lived token's ~60 day window — confirm the
      options page's "Reconnect soon" badge appears before expiry
      (`getExpiringPages()` in `src/background/auth.js`).
- [ ] Error messages read as plain English with an actionable suggestion (see
      `FacebookApiError.suggestion` in `src/background/facebook-api.js`); extend the
      `switch` there as new Graph API error codes are observed in production.
- [ ] Confirm the extension works in Incognito: enable "Allow in Incognito" for the
      unpacked/packed extension in `chrome://extensions` and smoke-test the golden
      path, since `chrome.identity.launchWebAuthFlow` and `chrome.storage.local` both
      behave slightly differently in Incognito-enabled contexts.
- [ ] Run `npm test` (unit tests for formatting/content-checks/timing logic) and fix
      any failures before tagging a release.

## Not required for MVP, tracked for Phase 2/3

- [ ] Bulk CSV scheduling (Phase 3).
- [ ] Instagram cross-posting, pending Meta API availability for the connected app
      (Phase 3).
- [ ] Draft → Manager review → Live approval workflow (Phase 3, Agency tier).
- [ ] Analytics snapshot via `/insights` (scaffolded in `getPageInsights()` in
      `src/background/facebook-api.js`, not yet wired into the UI).
